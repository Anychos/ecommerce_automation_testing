## P1 — усилить качество фреймворка

- [ ] **Закрывать каждый HTTPX client.**
  - Доказательство: API-fixtures возвращают clients напрямую, а у `BaseAPIClient` нет метода `close()`. Authentication clients, создаваемые private builders, также остаются открытыми.
  - Требуемое изменение: добавить `BaseAPIClient.close()`; перевести каждый API client fixture на `yield`/`finally`; закрывать временный authentication client после получения token.
  - Готово, когда: отдельные unit-тесты проверяют делегирование `close()`, а у каждого API fixture есть teardown.

- [ ] **Сделать cleanup тестовых данных надёжным.**
  - Доказательство: product factory очищает созданные товары, но user factory не хранит и не удаляет созданных пользователей. Ресурс, удалённый тестом, также может сломать teardown.
  - Требуемое изменение: учитывать тестовых пользователей и товары; удалять их в `finally`; считать уже удалённый ресурс ожидаемым результатом cleanup, но показывать остальные ошибки.
  - Готово, когда: повторные API-прогоны не оставляют пользователей и товары, а teardown остаётся зелёным после delete-сценариев.

- [ ] **Генерировать свежие данные обновления при каждом вызове factory.**
  - Доказательство: `update_product_factory` вычисляет Faker-значения в default-аргументах при импорте модуля.
  - Требуемое изменение: использовать `None` в defaults и создавать Faker-значения внутри вызова factory либо передать defaults в Pydantic `default_factory`.
  - Готово, когда: два вызова без явных значений создают независимые request data.

- [ ] **Исправить диагностику assertions.**
  - Доказательство: cart и order assertions содержат неверные названия полей, например product name выводится как `price`.
  - Требуемое изменение: сопоставить каждую подпись assertion с реально проверяемым полем.
  - Готово, когда: намеренно падающие unit-тесты показывают в сообщении верное имя поля.
